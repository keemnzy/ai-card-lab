> 2026-11-18 회의(김민지) 내용을 바탕으로 정리한 초안. 포지셔닝·네이밍·기능·기술 구조·보안 정책·다음 할 일.
> 같은 날 포지셔닝을 "디지털 명함"에서 "행사 기념품 겸 네트워킹 굿즈"로 정했다 (근거: [`research/market-research.md`](./research/market-research.md)).

## 1. 한 줄 정의

> **행사가 끝나도 서로를 기억하게 해 주는 기념품**
> *The event keepsake that helps people remember each other.*

밋업·컨퍼런스·박람회 주최사가 참가자에게 나눠 주는 **행사 로고가 들어간 3D 프린팅 NFC 키링**.
행사장에서는 아직 못 만난 사람이 **가려진 카드**로 보여 "다 만나고 싶은" 마음으로 네트워킹을 하게 만들고, 행사가 끝나면 만난 사람이 직접 낸 **퀴즈를 풀며 다시 기억**한다.
키링은 행사 뒤에도 **일상 디지털 명함**으로 계속 쓰고, 다음 행사에 들고 가면 그대로 이어진다.

## 2. 포지셔닝

### 왜 "디지털 명함"이 아니라 "행사 굿즈"인가

| | 디지털 명함으로 팔 때 | 행사 굿즈로 팔 때 |
|---|---|---|
| 경쟁 상대 | Popl, Blinq, V1CE, 슬라이스 등 (포화, Linq 철수) | 에코백·텀블러·티셔츠 같은 일반 행사 굿즈 |
| 사는 사람 | 개인 (한 명씩) | 행사 주최사 (참가자 수만큼 한 번에) |
| 3D 프린팅 키링 | "왜 카드가 아니라 키링?" | 행사 로고가 들어간 기념품이라 자연스러움 |
| 가장 가까운 경쟁자 Klik(Bizzabo) | – | Klik은 빌려주고 **회수**, Meetcha는 **가져가는** 기념품이라 도감이 남음 |

### 고객과 사용자

- **사는 사람(고객)**: 행사 주최사. 1차 시장은 실리콘밸리 등 해외 밋업·컨퍼런스·박람회, 국내 네트워킹 행사.
- **쓰는 사람**: 행사 참가자. 무료.
- **첫 고객(파일럿)**: GSSC 운영진 행사 → 결과를 들고 해외 밋업으로.

### 행사 크기별 상품 (안)

| 등급 | 대상 | 구성 |
|---|---|---|
| Lite | 20~50명 밋업 | 공용 디자인 키링 또는 카드/스티커 + 일반 칩(NTAG215), 행사 로고 스티커 |
| Standard | 50~300명 네트워킹 행사 | 행사 로고 3D 프린팅 키링 + 일반 칩, 행사 테마, 리캡 |
| Premium | 컨퍼런스·박람회 | 맞춤 키링 + 위조 방지 칩(NTAG 424 DNA), 리포트, 체크인 데스크 지원 |

### 행사 뒤에도 쓰게 만드는 장치 (기념품이 서랍에 들어가지 않게)

1. **행사 리캡**: "○○ 컨퍼런스에서 12명을 만났어요" 페이지·메일 + 만난 사람 퀴즈 다시 풀기
2. **일상 디지털 명함**: 행사 밖에서도 키링을 태그하면 내 명함이 열린다
3. **명함 저장소**: 도감을 행사별로 묶어 보고, 휴대폰 연락처(vCard)로 저장
4. **다음 행사에서 이어 쓰기**: 이미 키링이 있으면 새로 받지 않고 체크인만

종이 명함 촬영 저장(리멤버 방식)은 나중으로 미룬다. 국내는 리멤버가 압도적이고, 해외 밋업에서는 종이 명함보다 LinkedIn QR을 많이 쓴다.

## 3. 네이밍 후보

| 이름 | 의미 | 메모 |
|---|---|---|
| **Meetcha (밋챠)** ← 프로토타입 가칭 | Meet + "잡았다(catch-ya)" | 발음 쉬움, 수집 게임 느낌, 한·영 모두 자연스러움 |
| Tagit (태깃) | Tag + it | 동작이 바로 이름. 다만 흔한 단어라 상표·도메인 확인 필요 |
| 인연도감 | 만난 사람을 모으는 도감 | 한국어 행사용 서브 브랜드로 좋음 (예: "Meetcha 인연도감") |
| Hello Hunt | 인사 사냥 | 이벤트 모드 이름으로 적합 |
| Knock | 키링을 톡 대는 동작 | 짧고 기억하기 쉬움 |

추천 구조: **제품/서비스 = Meetcha**, 이벤트 모드 = "Hello Hunt", 수집 화면 = "인연도감".
상표 주의: "Kahoot", "포켓몬/Pokémon", "도감(Pokédex)" 류의 표현·캐릭터·아트는 쓰지 않는다. 메커니즘(퀴즈, 수집)만 차용한다. 확정 전에 KIPRIS 상표 검색과 도메인(.app/.kr)을 확인할 것.

## 4. 핵심 기능

1. **명함 프로필**: 이름, 직함·소속, 한 줄 소개·펀팩트, 외부 링크(LinkedIn, Instagram, GitHub 등).
2. **내 퀴즈 만들기**: 4지선다 1~5문제. 오늘 한 이야기나 펀팩트로 만든다.
3. **태그 → 발견**: 상대 키링에 폰을 대면 프로필이 열리고 "도감"에 저장된다.
4. **퀴즈로 기억하기**: 행사 후 도감에서 퀴즈를 다시 푼다. 제한 시간 10초, 빨리 맞힐수록 점수가 높다 (정답 시 500~1000점).
5. **메모·메시지**: 나만 보는 메모 + 상대에게 남기는 짧은 메시지.
6. **이벤트 모드(Hello Hunt)**: 체크인한 참가자가 가려진 카드로 보이고, 태그할 때마다 하나씩 열린다. 리더보드와 실시간 피드.
7. **주최사 기능**: 참가자 명단 가져오기(CSV, Luma·Eventbrite 연동은 이후), 체크인 데스크에서 키링을 태그하면 등록과 체크인이 한 번에, 행사 로고·색 테마, 통계 리포트.
8. **행사 리캡**: 행사가 끝나면 만난 사람 수, 만난 사람 목록, 퀴즈 다시 풀기.
9. **명함 저장소**: 도감을 행사별로 묶어 보기, 연락처(vCard)로 내보내기.

## 5. "토스 주변 100원" 같은 근거리 기능에 대해

회의에서 나온 토스 기능은 휴대폰끼리 근처에 있는지 알아내는 방식(블루투스, 초음파 등)을 쓴다. 이건 **네이티브 앱**이라 가능하다. 웹에서는 제약이 크다:

- Web Bluetooth: iOS Safari 미지원. 주변 기기를 "광고"하는 기능은 웹에서 사실상 불가.
- Web NFC: 안드로이드 Chrome만 지원. 단, **NFC 태그를 폰에 대서 URL 열기**는 iOS·안드로이드 모두 앱 없이 된다 → MVP는 이것만 쓴다.

웹으로 "주변 느낌"을 내는 대안 (MVP에 바로 넣을 수 있는 순서):
1. **행사장 체크인**: 입구에서 운영진 키링(또는 QR)을 태그하면 "지금 이 행사에 있는 사람" 목록에 들어간다. → 이게 이벤트 모드의 "행사장에 있는 사람"이 된다.
2. **실시간 알림**: 누가 나를 태그했거나 근처 테이블에서 퀴즈를 풀면 피드로 보여 준다 (WebSocket/SSE).
3. 정말 근접 감지가 필요해지면 그때 앱(React Native/Expo)으로 BLE를 붙인다. 위치 정보는 동의 받고 행사 시간에만 쓴다.

## 6. 기술 구조 (제안)

```
[키링 NFC 칩] --태그--> https://meetcha.app/t/{tagId}?e={암호화값}&c={MAC}
                               │
                        [웹앱 (Next.js, 모바일 웹)]
                               │  서명 검증, 세션 확인
                        [API 서버] ── [DB: Postgres]  ── [객체 저장소: 프로필 사진]
                               │
                        [실시간: 이벤트 모드 피드 (SSE/WebSocket)]
```

- **NFC 칩**: NTAG 424 DNA 권장. 태그할 때마다 칩이 카운터와 암호 서명(SUN/SDM)을 URL에 붙여 준다 → 서버가 진짜 칩을 태그했는지 확인할 수 있다. 일반 NTAG213/215는 싸지만 URL이 고정이라 복사·스크린샷 공유로 위조가 쉽다 (아래 보안 참고). 예산이 빠듯하면 MVP는 NTAG215 + 서버 측 보완으로 시작하고 기업 납품용부터 424 DNA로 간다.
- **키링 본체**: 3D 프린팅 시 NFC 스티커 위에 금속 도장·두꺼운 PLA를 피한다(인식 거리 저하). 스티커는 표면에서 2mm 이내.
- **프론트**: 모바일 웹 우선(앱 설치 없이 바로 열려야 네트워킹 현장에서 쓰인다). 로그인은 카카오/구글 OAuth 또는 이메일 매직 링크.
- **데이터 모델(초안)**
  - `users` (id, 이름, 직함, 소속, 한 줄 소개, 사진, 공개 범위)
  - `links` (user_id, 라벨, url)
  - `tags` (tag_uid, user_id, 칩 키 버전, 마지막 카운터, 상태: 활성/분실)
  - `quizzes` (user_id, 질문, 보기[4], 정답 인덱스, 순서)
  - `encounters` (scanner_id, owner_id, event_id, 시각) — 도감
  - `quiz_attempts` (scanner_id, owner_id, 점수, 시각)
  - `notes` (작성자 전용 메모), `messages` (보낸 사람, 받는 사람, 내용, 읽음)
  - `events` (기업 클라이언트, 이름, 시간, 테마), `event_attendees` (event_id, user_id, 체크인 시각)

## 7. 보안·개인정보 정책 (초안)

**태그 위조·남용**
- NTAG 424 DNA의 SUN 서명 + 카운터 검증. 이전 카운터 재사용(복사된 URL) 요청은 "도감 등록" 없이 공개 프로필만 보여 준다.
- 태그 1건 = 도감 1건. 같은 사람 반복 태그·자동화 요청은 계정·IP 단위 레이트 리밋.
- 키링 분실 시 마이페이지에서 즉시 비활성화, 새 키링에 재연결.

**정답·퀴즈 보호**
- 정답은 서버에만 둔다. 클라이언트에는 문제와 보기만 내려보내고 채점은 서버에서 한다 (프로토타입은 데모라 브라우저에서 채점함).
- 점수의 속도 가산은 서버가 문제 발급 시각 기준으로 계산.

**개인정보 (개인정보보호법 기준)**
- 수집 항목 최소화: 이름 외 전부 선택 입력. 연락처(전화번호)는 기본 수집하지 않고, 본인이 링크로 직접 공개할 때만 노출.
- 공개 범위 3단계: 전체 공개 / 나를 태그한 사람만 / 비공개. 기본값은 "태그한 사람만".
- 이벤트 모드에서 가려진 카드에 보이는 힌트(분야 등)는 본인이 고른 항목만, 행사 기간 중에만 노출.
- 상대에게 남긴 메시지는 받는 사람이 차단·신고할 수 있고, 메모는 작성자만 본다.
- 기업 클라이언트(행사 주최사)에 넘기는 리포트는 통계(참가자 수, 평균 만남 수)만. 개인별 데이터는 본인 동의가 있을 때만.
- 탈퇴 시 프로필·퀴즈·메시지 삭제, 다른 사람 도감의 내 카드는 "탈퇴한 사용자"로 표시.
- 보관 기간·제3자 제공·처리 위탁(클라우드 등)을 담은 개인정보처리방침과 이용약관 필요. 만 14세 미만 가입 제한.

**일반**
- HTTPS 전용, 외부 링크는 `https://`만 허용하고 `rel="noopener noreferrer"`로 연다.
- 사용자 입력은 전부 이스케이프(XSS), 프로필 사진은 서버에서 재인코딩·EXIF(위치정보) 제거.
- 관리자 페이지는 2단계 인증, 기업 클라이언트별 데이터 분리.

## 8. UI 흐름 (프로토타입에 구현된 것)

| 화면 | 내용 |
|---|---|
| 이벤트 | 진행률(2/8), 가려진 카드 그리드. 카드를 태그하면 "새로운 사람 발견!" 연출 후 공개 |
| 내 도감 | 만난 순서대로 목록, 퀴즈 최고점·만난 시각 |
| 프로필 | 한 줄 소개, 링크, 퀴즈 풀기, 나만 보는 메모, 메시지 남기기 |
| 퀴즈 | 10초 타이머, 4색 보기(▲◆●■), 정답 시 속도 비례 점수, 결과 화면 |
| 내 명함 | 프로필·링크 편집, 내 퀴즈 추가·삭제 |

프로토타입 데이터는 전부 예시이고 브라우저 localStorage에만 저장된다. 서버·실제 NFC 연동은 없다.
